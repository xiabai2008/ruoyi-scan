# Ruoyi-Scan v1.6.0 — 从「若依专项」到「国产 Java 框架矩阵」的第一步

v1.5.6 把「报出来的能不能信」做对了。本版做的是**横向扩展**——
第一次把扫描器从一个框架扩到第二个，并且全过程在真实站点上验证。

**54 → 56 个插件**（新增芋道 yudao 2 个）。

---

## 一、最重要的变化：先建真实站，再写插件

本轮有 **三次**「源码/记忆判断」被真实站推翻。这不是失误，是方法：

| 计划里写的 | 真实站上是什么 |
|---|---|
| Plus 定时任务加个误配配置就能 CONFIRMED | **5.6.2 已改用 SnailJob，端点根本不存在** |
| 任意文件读取在 4.5.1/4.6.2 上受影响 | **`checkAllowDownload()` 从 4.5.1 起就拦 `..`，漏洞不存在** |
| 芋道 `/jmreport/**` 是 `permitAll`，4 个插件可复用 | **源码确实写 permitAll，但模块自身还有一层校验，实测全部 401** |

共同规律：**源码里看到 permitAll / 配置项，不等于运行时可利用。**
中间件层、模块自身校验、二开改动都会改变结论。

所以本版新增两座靶场：**C5**（暴露但需认证）与 **Y1**（芋道真实站）。

## 二、新增框架：芋道 yudao

### 为什么是芋道

| 判据 | 芋道 | SpringBlade | Pig |
|---|---|---|---|
| 装机量（GH+Gitee） | **~152k** | ~28k | ~7k |
| 与若依血缘 | 直接 fork Pro 版，`/system/*` 同源 | 独立 RBAC | OAuth2，差异最大 |
| 已公开 CVE | **22 条，持续新增** | 16 | 4 |

Guns（原 ROADMAP 里的）建议移除：最后 push 2025-11-15，近一年停滞，
NVD 11 条命中全是「Quake3/Android 游戏」类噪声。

### 两个插件（都是实测发现的）

**芋道租户列表未授权**（medium）
`/admin-api/system/tenant/simple-list` 匿名可读全部租户 ID 与名称——多租户隔离的起点情报。

判据刻意严格：`code` 必须是 **0**（芋道成功码，不是若依的 200）、`data` 非空数组、
元素含 `id`+`name`。只判 `code==0` 会被 `/tenant/get-id-by-name` 的
`{"code":0,"data":null}` 骗到——那是「查不到」，不是泄露。

**芋道 Druid 监控未授权**（high）
`/druid/{datasource,sql,weburi}.json` 匿名返回真实监控数据。

根因是芋道默认把 `stat-view-servlet` 的 `login-username`/`login-password` **留空**：

```yaml
stat-view-servlet:
  enabled: true
  login-username:     # ← 空
  login-password:     # ← 空
  allow:              # ← 空 = 允许所有
```

泄露内容：数据源连接串、真实执行的 SQL、全部访问过的 URI。
对攻击者这是「内部结构地图」，比一个密码更值钱。

## 三、修掉一批「能力存在但被自己关掉」的缺陷

### 未授权类插件会产生假 CONFIRMED（最严重）

未授权类插件的被测命题是「**不登录**就能访问」。但它们复用共享会话，
而该会话可能已被「后台默认口令」插件登录污染。

客户现场会这样出事：

```
Swagger 开了但配了认证
→ 扫描器先跑默认口令拿到 admin 会话
→ Swagger 插件复用该会话 → 200 + 真实页面
→ 报「Swagger 未授权访问」
→ 客户复核「我们明明加了认证」，报告可信度归零
```

**17 个插件**（ruoyi 7 + spring 8 + yudao 2）统一改用 `session.anonymous()`。
C5 靶场的对照实验证明这是必需的：

| 场景 | 结果 |
|---|---|
| 无防护 + 已认证 | **CONFIRMED（假）**——证据写着「可匿名访问」实际带着凭据 |
| 有防护 + 已认证 | UNKNOWN——匿名克隆拿 401，正确判定 |

### 三处误判语义

- **`JSESSIONID` 被当认证信号**：任何 Java 应用匿名请求都会下发它 → 真实未授权被判 SAFE（假阴性，方向与三态纪律相反）
- **鉴权关键字含裸「登录」**：真实暴露页常含「退出登录」→ 判 SAFE
- **401 判 SAFE**：401/403 是「端点存在但拒绝访问」，应为 UNKNOWN。判 SAFE 等于告诉客户「你这套系统没开 Actuator」，而它明明开着

### RuoYi-Vue 3.x 被版本门整片跳过

3.x 与 4.x 是**两条并行版本线**，不是前后代——接口路径完全一致。
`>=4.0` 把线上最常见的分支整片排除，盲测里 R6(3.9.2)/R7(3.8.9) 各有 **9 个插件**被跳过。
现放宽到 `>=3.0`，被跳过数 9 → 2（只剩两个 CVE 类，那些绑定特定版本）。

## 四、工程债清偿

**Jeecg 的注册债**（v1.5.5 接入时只做了扫描路径，配套全漏）：

| 问题 | 修复 |
|---|---|
| `--cms jeecgboot` 被 argparse 拒绝 | 改为从插件包派生 |
| `--plugin-new --category jeecgboot` 抛错 | 同上（3 处） |
| `export_plugins()` 导不出 jeecg 插件 | 改为从包发现派生 |
| API 把 jeecg 插件标成 `cms=ruoyi` | 改从模块路径派生 |
| nightly acceptance 不跑 jeecg | 登记为待建 |

**并加了门禁** `scripts/check_framework_registration.py`——新增框架时漏任一处，CI 直接红。
本版新增芋道时它立刻生效了。
