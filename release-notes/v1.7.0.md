# Ruoyi-Scan v1.7.0 · 三态判定的可信度闭环

v1.6 解决的是「扫得全不全」，v1.7 解决的是**「凭什么信」**。

这一版不新增任何检测插件、不新增框架、不改扫描主流程；它把三态判定从「实现」升级为
可度量、可复现、可辩护的方法论：每条 UNKNOWN 都有原因码，效果指标换成带 Ground Truth
的 Precision / Recall / F1 / Youden J，插件数只保留一个事实源。

- 版本：**1.7.0**
- 插件数：**56**（ruoyi 20 / spring 14 / common 12 / jeecgboot 8 / yudao 2）
- 判定语义：**未改变** `CONFIRMED / SAFE / UNKNOWN` 的取值与含义

---

## 一、WP-1：UNKNOWN 不再是黑箱

### 为什么必须做

v1.6 复盘发现：61 份报告、1,849 条结果里有 **567 条 UNKNOWN（30.7%）**，但没人能回答
「这些到底是真测不了，还是被降级掉的正确答案」。更早的一次尝试按证据文本关键字归类，
把正确的登录墙降级误判成「误降级」——教训是：**原因必须由产生点写入，不能事后猜文本。**

### 做了什么

- `ScanResult` / `ComponentVersionResult` 新增一等字段 `unknown_reason`（additive，默认空）。
- 新增 `UnknownReason` 原因码：

| 原因码 | 含义 | 解锁方式 |
|---|---|---|
| `auth_wall` | 登录墙拦截（302→/login 或 200 登录页） | `--auth-login`；未授权类插件改用匿名视角 |
| `no_session` | 声明 `requires_auth` 但未取得高权会话 | `--auth-login` |
| `no_lowpriv` | 越权类缺低权账号 | `--surface-account` |
| `denied` | 401/403/429，端点存在但拒绝 | 不能据此判「不存在」 |
| `unreachable` | 网络异常/超时/OAST 无回调 | 检查连通性或重试 |
| `no_evidence` | SAFE 缺判定证据被降级 | 插件判定补强 |
| `blocked` | 全站 WAF 拦截 | WAF 绕过/降速 |
| `budget_exceeded` | 超出 `--time-budget`，本项未执行 | 调大预算 |
| `endpoint_absent` | 端点不存在（版本/架构差异） | 属正确行为 |
| `insufficient_evidence` | 插件自判证据不足 | 人工复核 |
| `unclassified` | 兜底，必须可计数 | 目标 <5% |

- 5 个降级点、引擎预算/认证降级/异常兜底、组件检测、编排收口点全部写入原因码。
- 历史/第三方插件没有原因码时，走 `lib/unknown_reasons.py` 的**受控固定前缀白名单**
  （只匹配扫描器自身代码生成的句式，不按目标响应文本猜；只填空值、不覆盖显式值）。
- 7 种报告格式（HTML/JSON/CSV/PDF/Word/Excel/SARIF）新增「未判定原因」列/属性；
  API `ScanResultDTO` 与 SARIF `properties.unknown_reason` 同步透出。

### 结果

盲测 v4 实际 51 份 `report.json`、**567 条 UNKNOWN**：

- 归因覆盖率：**100.00%**
- `unclassified`：**0**
- 逐类计数：`auth_wall` 168 / `no_lowpriv` 110 / `insufficient_evidence` 109 /
  `no_session` 73 / `no_evidence` 49 / `endpoint_absent` 39 / `denied` 12 /
  `unreachable` 2

审计命令：`python scripts/unknown_audit.py --check`；完整表见
[docs/unknown_audit_v1.7.md](../docs/unknown_audit_v1.7.md)。

## 二、WP-2：三态 vs 二态，用 GT 说话

### 实验设计

- 数据：`artifacts/blind_v2/gt/` 的逐站 GT（当前 27 个有 GT 文件）+ `data/acceptance_baseline.json`
  的 3 个签名靶场，归一化为 `(site, plugin, gt_label)` 表。
- 报告：`artifacts/blind_v4/*-anon/report.json`（匿名视角，与 GT 一致）。
- 三组：

| 组 | 判定口径 |
|---|---|
| G0 | 原始三态：CONFIRMED / SAFE / UNKNOWN |
| G1 | 二态·保守：UNKNOWN → SAFE（分析层映射） |
| G2 | 二态·激进：UNKNOWN → CONFIRMED（分析层映射） |

**二态折叠只在实验脚本读 `report.json` 后做，不修改扫描器运行时 `status`。**

### 结果（27 个可评估站点 / 243 条 GT 条目）

| 组 | Precision | Recall | F1 | Specificity | Youden J | TP/FP/FN/TN |
|---|---:|---:|---:|---:|---:|---|
| G0 三态 | 75.00% | 81.82% | 0.7826 | 97.81% | 0.7963 | 9/3/2/134 |
| G1 保守二态 | 75.00% | 81.82% | 0.7826 | 98.45% | 0.8026 | 9/3/2/190 |
| G2 激进二态 | 13.24% | 81.82% | 0.2278 | 69.43% | 0.5125 | 9/59/2/134 |

### 如实结论

**本数据集不支持 H1 的强形式**：G1 的 J 与 G0 相差 -0.0063，保守折叠的 P/R 与三态相同。
三态的价值不应表述为「提高 J」，而是**可解释性与风险分层**：

- 57 条 GT 覆盖的 UNKNOWN 中，**0 条是 GT 真漏洞**（56 条 GT safe + 1 条 GT unknown）；
- G2 的 Precision 只有 13.24%，激进折叠会把「测不了」批量变成误报，直接验证项目坚持三态的动机；
- 实验数据来自自建靶场与匿名视角，**不宣称生产环境检出率**。

完整实验报告：[docs/verdict_experiment_v1.7.md](../docs/verdict_experiment_v1.7.md)。
