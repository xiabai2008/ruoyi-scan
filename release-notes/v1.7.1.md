# Ruoyi-Scan v1.7.1 · 真实靶场回归修复（含 C3 蜜罐误报）

v1.7.0 在 R1/C3 真实靶场实测时发现两个与「UNKNOWN 结构化归因」直接相关的缺陷，
以及 C3 蜜罐两个**既有** B 类误报。v1.7.1 一并修复；不改变三态语义、不新增检测能力。

## 修复 1：去重聚合丢失 `unknown_reason`

**现象**：R1 扫描报告（默认 `dedup=True`）中所有 UNKNOWN 的 `unknown_reason` 为空，
HTML/CSV 的「未判定原因」列为空。单条结果、`--no-dedup` 时正常。

**根因**：`core/dedup.py::AggregatedVuln` 是报告前的鸭子类型聚合对象，v1.7 新增
`ScanResult.unknown_reason` 时没有同步它的字段、`to_dict()` 和 `aggregate()` 构造。
报告统一走 `_effective_results()` → `AggregatedVuln`，因此字段被静默丢弃。

**修复**：
- `AggregatedVuln` 新增 `unknown_reason` 字段；
- `to_dict()` 透出该字段；
- `aggregate()` 从组内首个非空值继承；最终状态为 CONFIRMED/SAFE 时清空（原因码只对 UNKNOWN 有意义）。

**回归测试加严**：旧测试只断言整行 CSV 含「登录墙拦截」，而证据正文里也有这个词，
所以去重丢字段时仍然绿。现改为按 CSV 列名定位「未判定原因」列，并直接断言
`AggregatedVuln.unknown_reason` / `to_dict()`。

## 修复 2：历史原因码白名单误归类

**现象**：R1 的「部门树越权访问」实际是「低权账号登录成功，但空列表不能证明越权」，
却被归成 `no_lowpriv`（缺少低权账号），误导用户去补账号。

**根因**：`lib/unknown_reasons.py` 的兼容白名单用子串「低权账号」匹配 `no_lowpriv`，
把「低权账号 scanner_low 登录成功…」也命中了。

**修复**：
- `no_lowpriv` 只匹配「缺少低权账号 / surface-account」；
- 「低权账号…登录成功」「登录成功」等无数据证据归到 `insufficient_evidence`；
- 部门树越权插件的所有 UNKNOWN 分支（缺账号、登录失败、请求异常、端点缺失、
  会话失效、形态矛盾、无业务形态、空列表）全部显式写 `unknown_reason`。

## 修复 3：C3 蜜罐 B 类误报（既有缺陷）

C3 的期望输出是 **2 CONFIRMED**（`.git` / `.env` 两条 A 类诱饵）。v1.7.0 实测多报了两条
B 类误报；用 v1.6.0 在同一 C3 复跑结果相同，确认**不是 v1.7 回归**。C3 的假端点：

| 端点 | C3 假响应 |
|---|---|
| `/swagger-ui.html` | 200 + 真实 Swagger UI 骨架页，引用 `/v2/api-docs` |
| `/v2/api-docs` | 200 + `{"swagger":"2.0","paths":{}}`（无任何接口） |
| `/druid/index.html` | 200 + Druid 登录页（`loginUsername`/`loginPassword`/`submitLogin`） |
| `/actuator/env` | 200 + 假 `propertySources`（有 `systemEnvironment`，无 `systemProperties`/`origin`） |

**修复**：
- `RuoYi Swagger 未授权访问`：只有文档 JSON 可解析且 `paths`/`urls`/`swagger-resources`
  有实际内容才判 CONFIRMED（新增 `lib.matcher.is_real_swagger_doc`）；UI 页只记为可达，
  不能单独成立。
- `未授权访问（批量）`：
  - Actuator 增加结构复核（新增 `lib.matcher.is_real_actuator_env`）：要求
    `propertySources` 为结构化数组，且存在 `systemProperties`/`server.ports`
    或带 `origin` 的配置项；
  - Druid 登录页不再算未授权监控台；
  - Swagger UI 需 `/v2/api-docs` 或 `/v3/api-docs` 返回非空文档。

**C3 复扫结果**：**2 CONFIRMED / 33 SAFE / 10 UNKNOWN**，仅 `.git` / `.env`；
两条误报均变为 SAFE，证据里写明「假 UI 页/文档为空」「Druid 登录页」「非真实 Actuator env」。

## 真实靶场回归结果（R1 / C3）

```text
python main.py -u http://127.0.0.1:19101 \
  --auth-login admin:admin123 \
  --surface-account scanner_low:LowPriv_2026 \
  --report artifacts/lab_v17/R1-c3fix --no-pause --no-cta
```

- R1 结果：**6 CONFIRMED / 19 SAFE / 4 UNKNOWN**，与靶场 demo 预期一致；
- 4 条 UNKNOWN 原因码：
  - 代码生成模块 SSTI → `insufficient_evidence`
  - 定时任务 RCE（未授权访问）→ `auth_wall`
  - 目录扫描（软 404 兜底）→ `insufficient_evidence`
  - 部门树越权访问（空列表）→ `insufficient_evidence`（修复前误为 `no_lowpriv`）
- 7 种报告全部生成，JSON/CSV/HTML 的「未判定原因」列有值；
- R11 负样本：**0 CONFIRMED**，UNKNOWN 均有原因码；
- C3 蜜罐：**2 CONFIRMED**（`.git` / `.env`），两条 B 类误报已消除。
