# Ruoyi-Scan v1.5.4 发布说明

> 发布日期：2026-11-01 ｜ 适用范围：桌面端 / Web API / CLI
>
> **一句话**：首次用 27 座仿真靶场对扫描器做黑盒盲测，修掉两个影响整类目标的 P0 级判定缺陷，并补齐中间件、鉴权场景的一批判定正确性；本版同时包含 v1.5.3 之后累积的桌面端质量门禁、退出码语义与安全收口。

---

## 🎯 本版主线：盲测 v2

不再用"对照扫描器源码搭出来的内置靶场"自证，而是把扫描器当黑盒：

- **27 座仿真靶场**：R1–R13 官方形态 / 变体 / 负样本，C1–C4（Jolokia、H2、Data REST、Config、SBA、Spring4Shell、Cloud Function、Redis / MinIO / RocketMQ / 三类 SSTI），D1 若依二开变形，A2 TOTP 双因子。
- **三方对照**：扫描器 vs nuclei v3.11.1（13202 模板） vs 手工验证；GT 由独立探测脚本给出，不看扫描器输出。
- **结果**：TP 10 / FN 1（已知边界）/ FP 0；8 条"需人工"逐条手工核实，全部是扫描器正确、GT 盲区。
- **hold-out 验证**：R13 盲测前全程未接触，唯一一次扫描四类行为全部符合设计（假 200 不误报、WAF 拦截诚实 UNKNOWN、真漏洞不遗漏）。

详细报告：[docs/blind_test_report_v2.md](https://github.com/xiabai2008/ruoyi-scan/blob/main/docs/blind_test_report_v2.md)

## 🔴 P0 修复（影响整类目标）

- **弱指纹排他加载，导致整包漏扫**：Spring 默认错误 JSON 曾被算作强指纹，`cms=spring` 时若依 / JeecgBoot 插件包**整包不加载**。实测两个真实存在的 SSTI 被判 0 CONFIRMED。现改为弱证据时保留原包并补加载三个包，强证据行为不变。
- **catch-all 路径回显被当成漏洞**：带 `/**` 兜底路由的站点，任意路径返回 200 且正文带请求路径，导致 3 条组件误报 + 60 个假备份，且长度/摘要比对全部失效。新增"剥掉路径看残留"判据，接入 `matcher` / `soft404` 及 3 个插件；真实 RocketMQ 控制台等合法页面不误伤。

## 🛠 判定正确性（盲测发现）

- **minio_unauth**：改探 S3 根路径的 `<ListAllMyBucketsResult>` XML，不再探控制台登录页；正向特征收紧为 S3 XML 结构。
- **rocketmq_unauth**：控制台探根路径（官方包 context-path 为空）。
- **freemarker_ssti**：鉴权墙（200 + `{"code":500,"message":"Token校验失败"}`）判 UNKNOWN，不再冒充 SAFE。
- **ruoyi_gen_rce**：对 `/tool/gen/preview` 做差分验证（无 payload 基线 vs 注入），不再只看可达性。

## ✨ 累积改进（v1.5.3 之后）

- **桌面端质量门禁**：ESLint `react-hooks` 静态检查 + 构建产物 CDP 冒烟（真实点击"新建扫描"并遍历导航页），均纳入 CI。
- **依赖清单一致性门禁**：`scripts/check_deps.py` 校验 requirements / pyproject 一致。
- **退出码语义补全**：新增 `EXIT_PARTIAL = 4`（有目标未扫到）；批量模式全不可达不再返回 0；`-f` 缺参数改为 2。
- **顶层包名冲突检测**：`lib/namespace_guard.py` 检测 site-packages 下 `core/common/lib/cli` 等顶层名冲突并给出可操作建议。
- **安全收口**：`--serve` 默认只监听 127.0.0.1；修复批量 + `--ci` 首个命中即中断的假覆盖问题。
- 文档：README 目录树修正、退出码文档统一、依赖清单漂移修复。

## 📥 升级方式

- **桌面端**：Release 页下载 `Ruoyi-Scan_1.5.4_x64-setup.exe`（安装版）或 `ruoyi-scan-desktop.exe`（免安装单文件）
- **CLI / PyPI**：`pip install -U ruoyi-scan`（或下载 `ruoyi-scan.exe`）
- **Web API / Docker**：重新构建镜像或部署

## 📝 升级提示

- **判定更严格**：catch-all 页面不再判 CONFIRMED，部分目标可能由 CONFIRMED 变为 UNKNOWN —— 这是诚实降级，不是漏报。
- **已知边界**：目录不可列且文件名不可预测的遗留 SQL（如 `/docs/ry_20210415.sql`）仍无法字典检出；建议先用 `--crawl` / `--js-extract` 收集真实路径，或从 `.git` / `.svn` 泄露中取文件名后定向验证。
