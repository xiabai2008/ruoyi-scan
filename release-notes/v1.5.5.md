# Ruoyi-Scan v1.5.5 发布说明

> 发布日期：2026-11-02 ｜ 适用范围：桌面端 / Web API / CLI
>
> **一句话**：检出能力版 —— 用真实组件靶场把盲测 v2 暴露的「该报的报不出来」补上：54 个插件中有 CONFIRMED 产出的从 29 个提升到 46 个，同时修掉分离版登录、Jeecg 双前缀与 CLI/报告口径三个实战缺陷。

---

## 🎯 本版主线：从「少误报」到「真检出」

v1.5.4 用 27 座仿真靶场做黑盒盲测，证明了误报控制变强（FP 0），但也量出一个尴尬事实：
**54 个插件里有 25 个在全部靶场上一次 CONFIRMED 都没有**。v1.5.5 就是补这半边：

- 建真实漏洞版靶场：JeecgBoot 3.6.3（8 个历史漏洞点）、RuoYi 二开站（未授权定时任务/代码生成注入）、
  真实 Spring 组件（Gateway 3.1.0、Spring Cloud Function 3.2.2、Tomcat Spring4Shell）、R8 Nacos。
- 按真实组件响应形态重写 Spring 判定，不再只认内置签名靶场的理想化响应。
- 用同一套扫描矩阵复测：**首次有产出的插件新增 17 个，v1.5.4 已有产出 0 丢失，安全模式 B 类误报 0**。

## 🛠 关键修复

- **前后端分离版自动登录（F10）**：nginx 只反代 `/prod-api` 的站点，根路径 `/login` 是 SPA 页面，旧逻辑 POST 到错误地址（405）。
  现按 API 前缀识别 RuoYi-Vue/Cloud、RuoYi-Vue-Plus（Sa-Token）、JeecgBoot 三类真实登录入口；分离版站点鉴权后扫描恢复可用。
- **JeecgBoot context-path 双前缀（F11）**：API 前缀提升后插件请求 `/jeecg-boot/jeecg-boot/...`，真实 Jeecg 目标会整包漏报；已修。
  同时支持积木报表常见的 `result.records` 包装分页。
- **Spring 真实响应形态（F12）**：
  - env 配置覆盖：认「POST 写入探针属性回显 + GET 回读」，兼容 204；
  - Gateway RCE：认 201 + `Location: /routes/{id}`，且探针路由判定后 **DELETE 清理**，不给目标留路由副作用；
  - SCF RCE：改用 **时序差分**（sleep 探针延迟 vs 基线），修复版快速拒绝不会误判。
- **CLI 与报告口径一致（F13）**：需登录插件的 CONFIRMED/SAFE 在打印前就按认证纪律降级为 UNKNOWN，不再出现「终端说存在、报告说未知」。

## 📥 升级方式

- **桌面端**：Release 页下载 `Ruoyi-Scan_1.5.5_x64-setup.exe`（安装版）或 `ruoyi-scan-desktop.exe`（免安装单文件）
- **CLI / PyPI**：`pip install -U ruoyi-scan`（或下载 `ruoyi-scan.exe`）
- **Web API / Docker**：重新构建镜像或部署

- 仍不识别自定义 context-path（如二开站点的 `/portal`），已知限制见报告；下一版候选。
- 剩余 8 个零产出插件均为已识别边界（recon 类、Shiro 指纹、Windows 靶场文件读取、Plus 误配站、无认证 Redis、备份靶场），
  不是「新版本漏报」。
