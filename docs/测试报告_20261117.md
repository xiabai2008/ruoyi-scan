## 五、问题清单

### P1 — 提示文案不准确（低优先级，非功能 bug）

**现象**：`--auth-login` 已登录成功的情况下，「定时任务 RCE（未授权访问）」仍提示「请求被登录墙拦截……可加 --auth-login 后重扫」。

**分析**：该插件走匿名 session 探测未授权访问（设计正确，不能带凭据判未授权），但提示文案写死了「可加 --auth-login」，在已认证场景下误导用户。

**建议**：提示文案改为区分当前是否已认证，例如「该项以匿名视角探测未授权访问，已认证会话不参与判定；如需验证需未认证环境」。

**位置**：推测在 `plugins/ruoyi/` 的定时任务 RCE 插件 UNKNOWN 分支（需 grep 该提示串定位）。

### P2 — eslint react-hooks 警告（低优先级）

**现象**：`desktop/src/state/widgets.tsx:248`，`useEffect` 依赖数组写 `[prefs.findings, prefs.engine, prefs.progress]`，eslint 要求把 `prefs` 整个加入依赖。

**分析**：`WidgetPrefs` 接口只有 `findings/engine/progress` 三个字段（见 `widgets.tsx:11-15`），当前写法在语义上等价，**不是真 bug**。但 lint 警告长期存在会稀释门禁信噪比。

**建议**：在 effect 内解构 `const { findings, engine, progress } = prefs`，依赖数组用三个解构变量；或加一行 eslint-disable 并注释说明（不推荐）。

### P3 — 环境注意：npm run build 在沙箱下失败（非项目缺陷）

**现象**：`npm run build` 失败，报 `[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED]`，vite 清空 `dist/assets`（161 文件）被沙箱批量删除保护拦截。

**分析**：这是 WorkBuddy 沙箱的安全策略，与代码无关。换 `npx vite build --outDir dist-verify --emptyOutDir false` 构建成功。用户在本机正常终端跑 `npm run build` 不受影响。

### P4 — 环境注意：靶场僵尸 PID

**现象**：测试前 34 座靶场全 DOWN，R1/R11/C1-2/C3 留有僵尸 PID 文件。

**建议**：每次测试前先 `python scripts/lab.py clean`，避免 `up` 时误判「已在运行」。README 已提示用 `lab.py status` 而非 netstat 判活，遵循即可。
