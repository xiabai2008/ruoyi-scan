 Ruoyi-Scan 操作命令手册
 版本：v1.5.2
 适用：Windows / Linux / macOS，Python 3.8+

【重要】本工具仅限授权测试
    只可扫描你拥有或已获得书面授权的目标系统。未授权扫描可能违反《网络安全法》
    与《刑法》第 285 条。演示时请使用本机靶场（见第 14 节）或自有资产。

 0. 30 秒速查（最常用的 8 条）
===============================================================================

    pip install -U ruoyi-scan
    ruoyi-scan -V
    ruoyi-scan -p http://127.0.0.1:8080/
    ruoyi-scan -u http://127.0.0.1:8080/
    ruoyi-scan -u http://127.0.0.1:8080/ --report .\reports\demo
    ruoyi-scan -u http://127.0.0.1:8080/ --components --report .\reports\demo
    ruoyi-scan -f targets.txt -p --report .\reports\batch
    ruoyi-scan --serve --host 127.0.0.1 --port 8123

    提示：只有显式写 --report <目录> 才会生成报告文件；不写只打印到屏幕。

    没有 Python？用终端版单文件 exe，参数完全一样，把 ruoyi-scan 换成 .\ruoyi-scan.exe：
    .\ruoyi-scan.exe -p http://127.0.0.1:8080/ --report .\reports\demo


===============================================================================
 1. 安装与启动
===============================================================================

1.1 pip 安装（推荐，带命令行）
-------------------------------------------------------------------------------
    pip install -U ruoyi-scan

    只装核心依赖（requests），体积最小。
    需要 PDF / Word / Excel 报告时：
    pip install -U "ruoyi-scan[report]"

    需要 Web 控制台 / API 时：
    pip install -U "ruoyi-scan[serve]"

    一次装齐常用能力：
    pip install -U "ruoyi-scan[report,serve,yaml]"

    安装完成后可直接使用 ruoyi-scan 命令；也可用 python -m 方式：
    python -m main -p http://127.0.0.1:8080/

1.2 桌面端（免 Python，双击即用）
-------------------------------------------------------------------------------
    文件：ruoyi-scan-desktop.exe（单文件版，约 49 MB）
    文件：Ruoyi-Scan_v1.5.2_x64-setup.exe（安装包，开始菜单 + 卸载项）

    单文件版：放到任意目录，双击运行。
    首次启动 3-5 秒：引擎自释放到 %LOCALAPPDATA%\Ruoyi-Scan\engine\，
    监听 127.0.0.1:8123，窗口自动连接。

    安装包版：双击安装（currentUser，无需管理员），从开始菜单启动。

    数据位置：
    报告    %USERPROFILE%\Ruoyi-Scan\reports\
    任务库  %USERPROFILE%\Ruoyi-Scan\tasks.db

    关闭窗口即退出；若界面被强杀，引擎随 JobObject 自动回收，不会残留 8123 端口。

1.3 终端版单文件 exe（免 Python，命令行）
-------------------------------------------------------------------------------
    文件：ruoyi-scan.exe（约 38 MB，PyInstaller onefile，console）

    它和 pip 版是同一条 CLI，参数完全一致；区别只是 Python 运行时已经打进去了。
    用法：在该目录打开 CMD / PowerShell，或把目录加进 PATH。

    .\ruoyi-scan.exe -V
    .\ruoyi-scan.exe -h
    .\ruoyi-scan.exe -p http://127.0.0.1:8080/ --report .\reports\demo
    .\ruoyi-scan.exe -u http://127.0.0.1:8080/ --report .\reports\full

    已内置的能力：54 个 POC、字典、组件 CVE 库、7 种报告格式、--serve Web 控制台、
    --distributed（redis 客户端已带，需自备 Redis 服务）。

    注意：
    - onefile 每次启动都要解压到临时目录，冷启动约 2-4 秒，属正常。
    - 双击 exe 只会打印帮助（等于不带参数），实际使用必须在终端里带参数。
    - 未显式写 --report 时，报告默认落到 %USERPROFILE%\Ruoyi-Scan\reports\。
    - 未签名 exe 可能被 SmartScreen 拦截：更多信息 -> 仍要运行。

1.4 Docker
-------------------------------------------------------------------------------
    docker build -t ruoyi-scan .
    docker run --rm ruoyi-scan -u http://host.docker.internal:8080/

1.5 源码运行（开发 / 需要内置靶场）
-------------------------------------------------------------------------------
    git clone https://github.com/xiabai2008/Ruoyi-Scan.git
    cd Ruoyi-Scan
    pip install -r requirements.txt
    python main.py -h

    注意：pip 包不包含 lab/ 靶场，靶场只在源码仓库里。

===============================================================================
 3. 四种扫描模式（核心）
===============================================================================

3.1 -p 漏洞检测（最快，只跑 POC 判定）
-------------------------------------------------------------------------------
命令：
    ruoyi-scan -p http://127.0.0.1:8080/

说明：
    跳过目录爆破和弱口令，只做指纹 + POC 验证，请求量小、速度快。
    适合：第一次接触目标、复测、CI 卡点。

真实输出（v1.5.2 对内置签名靶场，耗时 3.19s）：
    [*]当前扫描模式:[漏洞扫描]
    [*]指纹识别：cms=ruoyi 置信度=0.70 命中=['login:RuoYi', 'keyword:若依']
    [*]未检测到已知 WAF 特征
    [*]通用漏洞检测：已加载 12 个通用插件
    [*]存在任意文件读取
    [*]存在定时任务调用目标未校验
    [*]存在POST型报错注入（role）
    [*]存在POST型报错注入（dept）
    [*]存在任意文件上传
    [*]存在定时任务 RCE（未授权访问）
    [*]存在Thymeleaf/SpEL 模板注入
    [?]无法判定Redis 未授权访问: 连接失败: [WinError 10061] 由于目标计算机积极拒绝，无法连接。
    [/]不存在MinIO 未授权访问
    [/]不存在RocketMQ Dashboard 未授权
    [/]不存在Shiro RememberMe 反序列化（指纹）
    [*]扫描摘要：耗时 3.19s 风险分布 高12/中8/低0 合计 20 个漏洞

3.2 -m 目录扫描
-------------------------------------------------------------------------------
命令：
    ruoyi-scan -m http://127.0.0.1:8080/

说明：
    探测敏感路径、后台入口、actuator、备份文件、.git / .env 等。
    自带软 404 基线，避免 SPA 站点把任意路径都返回 200 造成假阳性。
    适合：先摸清攻击面，再决定跑哪些 POC。

3.3 -u 综合扫描（推荐给新用户）
-------------------------------------------------------------------------------
命令：
    ruoyi-scan -u http://127.0.0.1:8080/

说明：
    一条命令跑完整流程：指纹 -> WAF 识别 -> 目录扫描 -> POC -> 弱口令爆破 -> 报告。
    比 -p 多出目录扫描与爆破阶段，因此更慢，但覆盖最全。

真实输出（同一靶场，加 --pass-level top100，耗时 7.20s）：
    [*]存在Druid 弱口令爆破
    [*]存在后台默认口令（admin/admin123）
    [*]扫描摘要：耗时 7.20s 风险分布 高14/中8/低0 合计 22 个漏洞
    [*]去重统计：原始 30 条 -> 聚合后 29 条（1 组合并）

3.4 -l 登录爆破
-------------------------------------------------------------------------------
命令：
    ruoyi-scan -l http://127.0.0.1:8080/

    收敛字典（推荐，先跑 top100）：
    ruoyi-scan -l http://127.0.0.1:8080/ --pass-level top100

    只跑后台默认口令、跳过 Druid：
    ruoyi-scan -l http://127.0.0.1:8080/ --pass-level top1000

说明：
    --pass-level 三档：top100 / top1000 / full（默认 full）。
    内置 6 个 Druid 用户名 + 若依默认口令字典。
    对生产环境请务必先确认账号锁定策略，避免锁死管理员账号。

3.5 四种模式怎么选
-------------------------------------------------------------------------------
    只想快速确认有没有洞            -> -p
    想知道有哪些后台 / 敏感文件      -> -m
    第一次完整评估                  -> -u
    只关心弱口令                    -> -l
    时间紧、目标多                  -> -p --time-budget 60


===============================================================================
 4. 报告输出
===============================================================================

4.1 基本用法
-------------------------------------------------------------------------------
    ruoyi-scan -u http://127.0.0.1:8080/ --report .\reports\demo

    生成（默认 all，即全部 7 种）：
    report.html    交互式报告，含风险分布、合规映射、证据、修复建议
    report.json    机器可读，供 CI / 基线对比
    report.csv     表格
    report.pdf     需 pip install "ruoyi-scan[report]"
    report.docx    需 pip install "ruoyi-scan[report]"
    report.xlsx    需 pip install "ruoyi-scan[report]"
    report.sarif   GitHub Code Scanning 可直接接收

4.2 只出需要的格式
-------------------------------------------------------------------------------
    ruoyi-scan -u http://127.0.0.1:8080/ --report .\reports\demo --report-format html,json

4.3 报告命名与覆盖规则（重要）
-------------------------------------------------------------------------------
    文件名固定为 report.<ext>。
    同一个 --report 目录重复扫描会覆盖上一次结果。
    多目标批量扫描时，程序按目标自动建子目录（target_2、target_3 去重）。

4.4 报告里有什么
-------------------------------------------------------------------------------
    - 风险分布（只统计 CONFIRMED）
    - 合规映射：等保 2.0 条款 + OWASP Top 10 类别
    - 每条结果的 11 列：名称 / 严重度 / 状态 / URL / 证据 / 修复建议 /
      修复详情（nginx、Apache、IIS 配置片段与代码改法）/ 复现命令 / CVE / CVSS
    - UNKNOWN 单独列出，不混进漏洞数

4.5 整改复测
-------------------------------------------------------------------------------
    第一次扫描后保留 json：
    ruoyi-scan -u http://target:8080/ --report .\reports\base

    整改完成后复测并对比：
    ruoyi-scan -u http://target:8080/ --report .\reports\retest --remediation .\reports\base\report.json

    只对比两份已有报告（不重新扫描）：
    ruoyi-scan --diff-only .\reports\base\report.json .\reports\retest\report.json

    与历史报告对比：
    ruoyi-scan -u http://target:8080/ --report .\reports\new --diff .\reports\base\report.json


===============================================================================
 5. 常用增强参数
===============================================================================

5.1 并发与限速（默认 1 线程串行，最稳）
-------------------------------------------------------------------------------
    --threads 8          并发线程数（CLI 不限上限，建议 1-50）
    --rate 20            每秒最多 20 个请求，0 = 不限速
    --timeout 15         单请求超时秒数（默认 10）
    --time-budget 120    单目标总时间预算，超时后剩余插件记 UNKNOWN

    生产环境建议：--threads 5 --rate 10，别把业务打挂。

5.2 网络
-------------------------------------------------------------------------------
    --proxy http://127.0.0.1:7890
    --proxy-file proxies.txt
    --proxy-rotate round-robin
    --verify-tls          校验 TLS 证书（默认不校验，兼容内网自签名）
    --skip-preflight      跳过可达性预检（走特殊代理链路时用）

5.3 指纹与组件
-------------------------------------------------------------------------------
    --cms ruoyi           手动指定 CMS，跳过指纹识别
    --cms spring
    --components          组件版本检测并比对 20 个组件的 CVE
    --no-components       关闭组件检测

5.4 WAF
-------------------------------------------------------------------------------
    --bypass-waf auto     默认，识别到 WAF 才绕
    --bypass-waf on       强制绕过（11 种策略）
    --bypass-waf off      关闭
    --adversarial-transport   对抗型传输层，绕 Cloudflare / JS 挑战
                              需先装：pip install "ruoyi-scan[adversarial]"

5.5 信息收集
-------------------------------------------------------------------------------
    --crawl               主动爬虫
    --crawl-depth 3       爬虫深度
    --crawl-max-pages 100 最大页面数
    --subdomain           被动子域名枚举
    --js-extract          从 JS 里提取接口端点
    --portscan            扫描前先做端口扫描
    --ports 80,443,8080   自定义端口

5.6 扫描模板（一条命令换一套策略）
-------------------------------------------------------------------------------
    --template quick        快速：只跑高危 + 目录扫描，1-3 分钟
    --template deep         深度：全量 + 爬虫 + JS + 子域名，10-30 分钟
    --template compliance   只跑带 OWASP 映射的插件
    --template dengbao      只跑带等保 2.0 映射的插件

    用法（模板必须配合扫描模式）：
    ruoyi-scan -u http://target:8080/ --template quick --report .\reports\quick
    ruoyi-scan -u http://target:8080/ --template dengbao --report .\reports\dengbao

5.7 YAML 配置文件
-------------------------------------------------------------------------------
    ruoyi-scan --config .\examples\scan.yaml

    适合把常用参数固化，避免每次敲一长串。

 6. 批量扫描
===============================================================================

6.1 准备目标文件 targets.txt（每行一个 URL，支持 # 注释）
-------------------------------------------------------------------------------
    http://10.0.0.11:8080/
    http://10.0.0.12:8080/
    # 下面这行是注释，不会扫
    https://demo.example.com/

6.2 执行
-------------------------------------------------------------------------------
    ruoyi-scan -f targets.txt -p --report .\reports\batch

    必须带 -u / -m / -p / -l 之一，否则程序直接报错并提示。
    每个目标生成独立报告，互不覆盖。


===============================================================================
 7. 认证扫描（登录后才能测的漏洞）
===============================================================================

7.1 自动登录（最省事）
-------------------------------------------------------------------------------
    ruoyi-scan -u http://target:8080/ --auth-login admin:admin123

    格式是 用户名:密码，不是 URL。
    会自动走若依登录链（含验证码识别与重试）。

7.2 直接注入 Cookie / Header
-------------------------------------------------------------------------------
    ruoyi-scan -u http://target:8080/ --auth cookie=JSESSIONID=abc123

    ruoyi-scan -u http://target:8080/ --auth bearer=eyJhbGciOi...

    可多次指定 --auth，参数会合并。

7.3 从文件加载
-------------------------------------------------------------------------------
    文件 auth.txt 内容（两种写法都支持）：
    type: cookie
    JSESSIONID: abc123
    token: xyz

    或纯 Cookie 字符串：
    JSESSIONID=abc123; token=xyz

    命令：
    ruoyi-scan -u http://target:8080/ --auth-file .\auth.txt

7.4 登录态深度扫描（资产盘点 + 越权矩阵）
-------------------------------------------------------------------------------
    ruoyi-scan -u http://target:8080/ --auth-login admin:admin123 --auth-surface

    带低权账号做垂直越权对比：
    ruoyi-scan -u http://target:8080/ --auth-login admin:admin123 --auth-surface --surface-account test:test123

    资产清单落盘：
    ruoyi-scan -u http://target:8080/ --auth-login admin:admin123 --auth-surface --surface-output .\assets.json

    注意：--auth-surface 需要真实有权限差异的账号，两边权限相同则测不出越权。


===============================================================================
 8. 弱口令与字典
===============================================================================

    --pass-level top100     只跑前 100 条，最快
    --pass-level top1000    前 1000 条
    --pass-level full       全量（默认）

    建议顺序：top100 摸底 -> 有线索再 top1000 -> 确认无锁定策略后才 full。


===============================================================================
 9. Web 控制台 / API / 定时扫描
===============================================================================

9.1 启动
-------------------------------------------------------------------------------
    ruoyi-scan --serve --host 127.0.0.1 --port 8123

    浏览器打开：
    http://127.0.0.1:8123

    API 文档：
    http://127.0.0.1:8123/docs

    首次使用需安装：pip install "ruoyi-scan[serve]"

9.2 加鉴权（对外开放时必做）
-------------------------------------------------------------------------------
    ruoyi-scan --serve --host 0.0.0.0 --port 8123 --api-key key1:read,key2:scan,key3:admin

    请求时带 X-API-Key 头。
    不设 API Key 时仅允许 127.0.0.1 访问。

9.3 定时扫描
-------------------------------------------------------------------------------
    ruoyi-scan --serve --schedule "0 2 * * *" --schedule-target http://target:8080/

    every 写法（每 3600 秒一次）：
    ruoyi-scan --serve --schedule every:3600 --schedule-target http://target:8080/

    注意：--schedule 与 --schedule-target 必须成对出现，少一个会直接报错退出。

9.4 任务持久化位置
-------------------------------------------------------------------------------
    --db-path .\data\tasks.db

 10. CI/CD 集成
===============================================================================

10.1 失败阈值
-------------------------------------------------------------------------------
    ruoyi-scan -u http://target:8080/ --ci --severity-threshold high --report .\reports\ci

    发现 >= high 的确认漏洞时进程以非 0 退出，流水线自动失败。
    阈值可选 low / medium / high。

10.2 生成流水线配置
-------------------------------------------------------------------------------
    ruoyi-scan --ci-init github
    ruoyi-scan --ci-init gitlab
    ruoyi-scan --ci-init jenkins

10.3 SARIF 接 GitHub Code Scanning
-------------------------------------------------------------------------------
    ruoyi-scan -u http://target:8080/ --ci --report .\reports\ci --report-format sarif

 11. 插件开发
===============================================================================

11.1 生成模板
-------------------------------------------------------------------------------
    ruoyi-scan --plugin-new my_check --category ruoyi

    或旧写法：
    ruoyi-scan --plugin-init my_check --category common

    生成后按 PluginBase 三态契约实现 verify()。

11.2 校验
-------------------------------------------------------------------------------
    ruoyi-scan --plugin-check .\plugins\ruoyi\my_check.py

11.3 加载外部插件扫描
-------------------------------------------------------------------------------
    ruoyi-scan -p http://target:8080/ --plugin-path .\my_plugins\

11.4 导出与签名（模板仓库）
-------------------------------------------------------------------------------
    ruoyi-scan --plugin-export .\exported
    ruoyi-scan --plugin-manifest .\exported
    ruoyi-scan --plugin-update

    模板仓库强制 Ed25519 验签，需 cryptography 与可信公钥。


===============================================================================
 12. 进阶能力（按需）
===============================================================================

12.1 利用链（验证危害，不只是报洞）
-------------------------------------------------------------------------------
    ruoyi-scan --chain-list
    ruoyi-scan --chain ruoyi_sql_to_rce -u http://target:8080/
    ruoyi-scan --chain ruoyi_defaultpw_to_webshell -u http://target:8080/
    ruoyi-scan --chain ruoyi_nacos_to_dbcreds -u http://target:8080/

12.2 OAST 带外检测
-------------------------------------------------------------------------------
    先起回调服务器：
    ruoyi-scan --oast-server --oast-host 0.0.0.0 --oast-port 5555

    再扫描：
    ruoyi-scan -p http://target:8080/ --oast

12.3 被动代理模式（浏览器走代理，边浏览边记录）
-------------------------------------------------------------------------------
    ruoyi-scan --passive --passive-host 127.0.0.1 --passive-port 8080

12.4 nuclei 模板兼容
-------------------------------------------------------------------------------
    ruoyi-scan -u http://target:8080/ --nuclei .\my-templates\
    ruoyi-scan -u http://target:8080/ --nuclei .\templates\ --nuclei-tags cve,ruoyi
    ruoyi-scan -u http://target:8080/ --nuclei .\templates\ --nuclei-severity high,critical
    ruoyi-scan --nuclei-validate .\templates\

12.5 分布式（大规模批量，需 Redis）
-------------------------------------------------------------------------------
    安装依赖：
    pip install "ruoyi-scan[distributed]"

    Master（分发目标，等待 Worker 回报后聚合）：
    ruoyi-scan --distributed master --redis-url redis://127.0.0.1:6379 -f targets.txt -p

    Worker（可多机多开，从队列领任务执行）：
    ruoyi-scan --distributed worker --redis-url redis://127.0.0.1:6379

    限制 Worker 领满 N 个任务后自动退出：
    ruoyi-scan --distributed worker --redis-url redis://127.0.0.1:6379 --worker-max-tasks 100

    单机多线程分发（不需要 Redis）：
    ruoyi-scan --distributed standalone -f targets.txt -p

    全局任务限速（写在 Worker 上，多个 Worker 传同一个值，令牌桶在 Redis 共享）：
    ruoyi-scan --distributed worker --redis-url redis://127.0.0.1:6379 --distributed-rate 20

    Master 等待结果的超时（默认 600 秒）：
    ruoyi-scan --distributed master --redis-url redis://127.0.0.1:6379 -f targets.txt -p --distributed-timeout 3600

    注意：
    - master 与 standalone 必须用 -f 或 -u/-m/-p/-l 给出目标，否则直接返回参数错误。
    - 扫描模式跟随 -u/-m/-p/-l；master 分发时会把模式写进任务，Worker 按同一模式执行。
    - 聚合报告固定输出到 reports\distributed_report.json。
    - --distributed-rate 限的是「每秒启动几个目标」，不是每秒请求数；单目标内部的
      请求节奏仍由 --threads / --rate 控制。
    - Redis 地址支持环境变量 REDIS_URL，命令行 --redis-url 优先。
    - master / worker 连不上 Redis 会直接报错退出（非 0），不会静默降级；要单机用 standalone。

12.6 异步引擎（大目标提速）
-------------------------------------------------------------------------------
    ruoyi-scan -p http://target:8080/ --async --async-workers 20

    注意：--async 与 --threads 是两套并发模型，大规模目标才用；不确定就保持默认。

12.7 结果缓存
-------------------------------------------------------------------------------
    ruoyi-scan -p http://target:8080/ --cache --cache-ttl 3600
    ruoyi-scan --cache-stats
    ruoyi-scan --cache-clear

12.8 AI 辅助（可选）
-------------------------------------------------------------------------------
    ruoyi-scan --ai "若依后台某接口存在SQL注入" --ai-validate
    ruoyi-scan -u http://target:8080/ --ai-triage
    ruoyi-scan -u http://target:8080/ --report .\reports\ai --ai-report zh

    API Key 走环境变量 RUOYI_AI_API_KEY，无 Key 时降级为规则模板。

12.9 漏洞知识库 / SIEM
-------------------------------------------------------------------------------
    ruoyi-scan --wiki
    ruoyi-scan -u http://target:8080/ --siem-export json --siem-output .\siem.json
    ruoyi-scan -u http://target:8080/ --siem-syslog 10.0.0.5:514 --siem-protocol udp

    SIEM 支持格式：ecs / cef / leef / json（可逗号组合）。


===============================================================================
 13. 三态判定怎么读（这是本工具的核心）
===============================================================================

    CONFIRMED  确认存在
        拿到了直接证据：回显的文件内容、注入标记、可执行的命令结果。
        报告里计入漏洞数。

    SAFE       确认不存在
        测过了，并且在目标当前版本 / 配置下被排除。
        注意：SAFE 不是「没测出来」，是「验证过不存在」。

    UNKNOWN    无法判定
        网络异常、超时、WAF 拦截、验证码阻断、需要登录等原因导致测不了。
        永远不冒充 SAFE，报告里单列，建议人工复核。

    为什么重要：
        通用扫描器未命中时报告里什么都不写，你无法区分「没洞」和「没测」。
        Ruoyi-Scan 对每个插件都给结论，报告才能作为交付物。

    看输出的颜色：
        绿色 [*] 存在    = CONFIRMED
        红色 [/] 不存在  = SAFE
        黄色 [?] 无法判定 = UNKNOWN

 14. 本地签名靶场（录视频 / 教学演示用）
===============================================================================

    仅源码仓库自带，pip 包不含。需要 Flask。

    14.1 安装靶场依赖
    ---------------------------------------------------------------------------
    pip install flask

    14.2 启动带洞靶场（端口 8080）
    ---------------------------------------------------------------------------
    Windows CMD：
    set LAB_MODE=vuln
    set LAB_PORT=8080
    python lab\server.py

    PowerShell：
    $env:LAB_MODE="vuln"; $env:LAB_PORT="8080"; python lab\server.py

    Linux / macOS：
    LAB_MODE=vuln LAB_PORT=8080 python lab/server.py

    14.3 启动全修复靶场（用来演示零误报，端口 8081）
    ---------------------------------------------------------------------------
    set LAB_MODE=safe
    set LAB_PORT=8081
    python lab\server.py

    14.4 对拍
    ---------------------------------------------------------------------------
    ruoyi-scan -p http://127.0.0.1:8080/ --report .\reports\lab_vuln
    ruoyi-scan -p http://127.0.0.1:8081/ --report .\reports\lab_safe

    预期：8080 出多个 CONFIRMED；8081 全部 SAFE 或 UNKNOWN，零误报。

    14.5 停止
    ---------------------------------------------------------------------------
    在靶场窗口按 Ctrl+C。

 15. 退出码（写流水线时用）
===============================================================================

    0     扫描完成且未触发阈值
    1     扫描发现达到 --severity-threshold 的确认漏洞（仅 --ci 模式）
    2     参数无效 / 扫描过程异常
    3     目标不可达（扫描前预检失败，一个目标都没扫到）
    4     批量扫描时有目标未扫到（覆盖面不全，需人工确认漏扫目标）

    非 CI 模式下即使发现漏洞也返回 0，避免手工执行被误判为失败。
    批量模式（-f）会扫完全部目标后统一判定，不会因首个目标命中漏洞而中断。

 16. 常见问题
===============================================================================

Q1  提示「python 不是内部或外部命令」
    Windows 安装 Python 时没勾 Add to PATH。重装勾选，或改用桌面端 exe。

Q2  pip 装完提示 ruoyi-scan 不是内部或外部命令
    Scripts 目录不在 PATH。用 python -m main 代替，或把
    %LOCALAPPDATA%\Programs\Python\Python3xx\Scripts 加进 PATH。

Q3  扫描一开始就退出，提示目标不可达
    先确认 URL 带协议和端口：http://ip:8080/，不要只写 ip。
    确实走特殊代理链路时加 --skip-preflight。

Q4  全是 UNKNOWN
    常见原因：目标挂了、WAF 拦了、需要登录、超时太短。
    处理顺序：--timeout 20 -> --bypass-waf on -> --auth-login 或 --auth cookie=...
    仍不行就人工复核，不要当成「没洞」。

Q5  大量 200 但不是真漏洞
    确认用的是 v1.5.2；目录扫描已内置软 404 基线。若目标是自己改过的
    SPA，先用 -p 只跑 POC 验证。

Q6  PDF / Word / Excel 报告没生成
    缺可选依赖：pip install -U "ruoyi-scan[report]"
    桌面端内置依赖情况以实际为准；录制演示时建议只勾 html/json/csv。

Q7  报告被覆盖了
    report.<ext> 是固定名。每次扫描换一个 --report 目录。

Q8  8123 端口被占用
    已有引擎在跑（桌面端会复用）。先关掉旧窗口，或
    netstat -ano | findstr :8123 找到 PID 后结束。

Q9  桌面端双击没反应
    删除 %LOCALAPPDATA%\Ruoyi-Scan\engine\ 后重试。
    Win10 早期版本需装 WebView2 Runtime。

Q10 杀软报毒
    PyInstaller 单文件打包的常见误报。用安装包版，或核对 checksums-desktop.txt。

Q11 -l 爆破把管理员账号锁了
    生产环境先确认锁定策略，用 --pass-level top100 收敛，或改用 --auth 注入已有会话。

Q12 想扫若依之外的 Spring 站点
    ruoyi-scan -u http://target:8080/ --cms spring
    54 个插件里含 14 个 Spring Boot 专项与 12 个通用插件。

 17. 参数速查（按功能）
===============================================================================

    扫描模式
    -u <url>            综合扫描
    -m <url>            目录扫描
    -p <url>            漏洞检测
    -l <url>            登录爆破
    -f <file>           批量目标文件（需配合上面任一模式）

    通用
    --threads <n>       并发线程
    --rate <n>          每秒请求上限
    --timeout <n>       请求超时
    --time-budget <s>   单目标时间预算
    --cms ruoyi|spring  指定 CMS
    --proxy <url>       代理
    --proxy-file <f>    代理池
    --verify-tls        校验证书
    --skip-preflight    跳过预检

    报告
    --report <dir>      报告目录
    --report-format      html,json,csv,pdf,docx,xlsx,sarif
    --report-template   docx 合规模板
    --remediation <json> 整改复测
    --diff <json>       与历史报告对比
    --no-dedup          关闭去重

    认证
    --auth-login <u:p>  自动登录
    --auth <k=v>        cookie= / bearer= / header=
    --auth-file <path>  认证文件
    --auth-surface      登录态资产盘点 + 越权矩阵

    策略
    --template <name>   quick/deep/compliance/dengbao
    --pass-level <lvl>  top100/top1000/full
    --bypass-waf <m>    auto/on/off
    --adversarial-transport
    --components        组件 CVE 比对

    服务与集成
    --serve             启动 Web 服务
    --host / --port     监听地址 / 端口
    --api-key <k>       API Key 分级
    --schedule <cron>   定时扫描
    --ci                CI 模式
    --severity-threshold low|medium|high
    --ci-init github|gitlab|jenkins
    --distributed master|worker|standalone  分布式扫描（需 redis 依赖）

    其他
    --plugin-list       插件清单
    --plugin-new <n>    新建插件脚手架
    --plugin-check <p>  校验插件
    --plugin-path <dir> 加载外部插件
    --chain-list        利用链清单
    --lang zh|en        报告语言
    -V                  版本
    -h / --help         帮助
